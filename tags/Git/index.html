Hexo博客中的两个Git仓库解析

Hexo博客中的两个Git仓库解析

在使用Hexo搭建博客并部署到GitHub Pages的过程中，你可能会注意到项目根目录下有两个Git相关的文件夹：.git/ 和 .deploy_git/。本文将详细解释这两个仓库的作用和区别。

📁 两个Git仓库的作用

1. .git/ - 源码仓库

这是您的博客源码仓库，包含：

  • 原始的Markdown文章文件
  • 主题配置文件
  • 博客的配置文件（_config.yml）
  • 主题源码
  • 所有开发相关的文件

远程仓库地址: https://github.com/zuoyecihua2023/ceshi.git

2. .deploy_git/ - 部署仓库

这是Hexo自动创建的部署专用仓库，包含：

  • 生成的静态网站文件（HTML、CSS、JS）
  • 已编译的主题样式
  • 优化后的图片和资源文件

远程仓库地址: https://github.com/zuoyecihua2023/zuoyecihua2023.github.io.git

🔄 工作流程

整个工作流程如下：

  1. 开发阶段: 在源码仓库中编写文章、修改配置
  2. 生成阶段: 运行 hexo generate 生成静态文件到 public/ 目录
  3. 部署阶段: 运行 hexo deploy 将静态文件推送到部署仓库
  4. 发布阶段: GitHub Pages 自动从部署仓库构建网站

💡 为什么要分开？

1. 源码安全

源代码和配置文件保存在 ceshi 仓库中，便于版本控制和协作。即使部署出现问题，源码仍然安全。

2. 部署效率

只推送编译后的静态文件到 GitHub Pages，减少部署时间和仓库大小。

3. 分离关注点

开发和部署分离，更清晰的管理方式：

  • 源码仓库专注于内容创作和配置管理
  • 部署仓库专注于网站发布

4. GitHub Pages要求

GitHub Pages 通常要求仓库名为 username.github.io 格式，而源码仓库可以使用任意名称。

⚠ 注意事项

  1. 不要手动修改 .deploy_git/ 目录

    • 该目录由 Hexo 自动管理
    • 手动修改会在下次部署时被覆盖

  2. 源码备份很重要

    • 定期将源码推送到远程仓库
    • 建议设置自动备份脚本

  3. 部署前先生成

    • 确保运行 hexo generate 后再部署
    • 推荐使用 hexo clean && hexo g && hexo d 完整流程

  4. 主题更新后记得部署

    • 修改主题配置后需要重新生成和部署
    • 自定义样式修改后也需要重新部署

🎯 最佳实践

  1. 版本控制策略

    • 源码仓库：管理文章、配置、主题修改
    • 部署仓库：由 Hexo 自动管理，无需人工干预

  3. 多设备同步

    • 在新设备上先克隆源码仓库
    • 安装依赖：npm install
    • 继续正常的开发流程
